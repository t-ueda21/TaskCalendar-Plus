# 設定11ページへの再編・命名整理・リファクタリング

2026年10月8日。ユーザーが承認した11ページ構成を実装し、「アップデート」と「説明」を分離しました。今回は `refactor-with-baseline` と `Do Not Lie` を使用し、仕様変更と純粋な内部整理を別段階で検証しています。バージョンは3.0.0、未リリースです。

## 担当と段階

| 担当 | エージェント | 範囲 |
|---|---|---|
| A | `/root/settings_a` | 初期状態、試験設計、11ページの成功基準、補足導線 |
| B | `/root/settings_b` | 承認構成の実装、その後の内部整理 |
| C | `/root/settings_c` | 独立した全試験・画面・性能・命名・互換性確認 |
| 調整 | `/root` | 証跡と差分確認、現在の文書・画像更新、develop反映 |

最初の8ページは175必須成功・20画像で保存しました。11ページ化と名前の修正を実施後、178必須が成功した状態をbeforeとして固定しました。その後だけを純粋なリファクタリングの比較対象にしています。

## 効果と限界

| 指標 | 初期8ページ | 11ページ化後・整理前 | 整理後 |
|---|---:|---:|---:|
| 本体ファイル数 | 62 | 62 | 61 |
| 本体容量（bytes） | 1,561,424 | 1,568,003 | 1,567,956 |
| 物理行数 | 33,569 | 33,632 | 33,530 |
| 非空行数 | 31,587 | 31,650 | 31,553 |

純粋な整理は**1ファイル・102物理行・97非空行・47 bytes減**です。容量効果はほぼありません。11ページ化を含む全体では**6,532 bytes増**です。試験・文書・画像・資産・設定と、Rust内の試験は本体から除いています。行数はコメントを含み、厳密なSLOCではありません。

同じPC・Node v24.18.0・Chromium 151.0.7922.34・Playwright 1.62.1で、16指標をウォームアップ2回後に各7回測定しました。100/1,000/10,000件の固定データと合成APIを使い、他の試験・ビルドと並行させていません。許容差は各指標max(35%,3ms)、Store読込のみmax(35%,10ms)です。

Store読込中央値は21.0→20.9ms、10,000件の索引・月集計は1.2→1.2msでした。全指標が許容内ですが、**明確な高速化は確認していません**。設定画面の初期化時間やネイティブ起動・メモリは専用計測していません。主な改善は、後からDOMを移し替える処理をなくし、ソース上の配置と責務を一致させたことです。
