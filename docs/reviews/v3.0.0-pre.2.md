# v3.0.0-pre.2 修正・検証記録

## Outlook取得時のクラッシュ

利用者から「画面表示後に落ちる」「手動取得・自動同期のどちらでも落ちる」と報告がありました。

3.0で追加した`task_property`は、予定を読む際に`UserProperties.Find("TCPlusTaskKey", true)`でアプリ用の識別情報を確認します。通常のOutlook予定では、この情報が存在しないことがあります。[Microsoftの仕様](https://learn.microsoft.com/en-us/office/vba/api/outlook.userproperties.find)では、見つからない場合にNothingが返ります。

使用ライブラリwinsafe 0.0.28は`VT_DISPATCH`の戻り値を変換するとき、nullでも`AddRef`を呼びます。空かどうかをアプリが調べる前に、null参照でプロセスが終了する経路がありました。

実Outlookを起動しない偽COMオブジェクトで、実際の`task_property`を呼び出しました。修正前は`null pointer dereference occurred`に続いてテストプロセスが終了し、終了コードは`0xc0000409`でした。修正後は同じ応答が正常に`None`として処理されます。

予定取得側の属性検索、登録先フォルダーの属性定義検索、登録時の予定属性検索の3か所を、変換前に空ポインターを確認する共通処理へ変更しました。以前のGetFirst/GetNextのS_FALSE対応も維持しています。以下をCOM応答テストで確認しています。

- S_OK/S_FALSEとEMPTY/NULL/null DISPATCHの組み合わせ。
- 属性が存在する場合の値と参照カウントの保持。
- Findの1引数・2引数と、COMへ渡す引数の逆順。
- 本当のCOMエラーと不正な返却型は、未検出と混同しない。
- 相互運用するVARIANT/EXCEPINFOのサイズ・アラインメント。

手動取得と自動同期はこの共通取得経路を使うため、報告された発生条件と整合します。ただし、利用端末の障害記録との照合と実Outlookでの解消確認は未実施です。クラッシュを再現したのは、アプリ本体やOutlookではなく専用のテストプロセスです。

## 表示と互換性

| 要求 | 反映・確認 |
|---|---|
| 天気アイコン | v0.2.1のSVGを内蔵。旧キャッシュのアイコン名や絵文字に依存せず天気コードから描画。日本語・英語・韓国語を確認 |
| 合計・残業の面積 | 横1行、12px。1440×1000の同条件で高さ66pxから18pxへ変更。幅306pxは同じ |
| 分まで表示 | 0時間0分・1時間0分・4時間30分を確認。日次の合計・残業非表示は維持 |
| 下部の余白 | カレンダー・一覧・AIの外周を12pxに統一。設定本文の末尾にも余白を保持 |
| 設定の階層 | 目次の背景、本文の見出し帯、操作欄の整列。目次の分類名を太字、配下の項目を字下げ |
| アクセントカラー | 色見本を右揃え。狭い画面でも右寄せ |
| 既存の設定操作 | 11ページ、保存・取消・保存失敗時の入力保持、キー操作を確認 |

画面検証は隔離Chromium・合成API/天気/ネイティブ応答で実施。11ページを1440pxと600px幅で確認し、ダーク表示や英語・韓国語・ドイツ語を含む32枚を記録しました。設定項目の水平はみ出し・画面エラーはありませんでした。さらに既存のUI操作契約38件を確認しています。

v0.2.1側の変更を照合し、天気SVGに加えて日付移動欄の曜日とトレイのアプリ名表示も復元しました。Outlook列挙のS_FALSE修正はpre.1で反映済みです。
