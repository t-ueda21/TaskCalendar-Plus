# 機能維持の基準（2026-09-27）

対象は開始時点の作業ツリー。未コミットのUI・アイコン・天気・Outlookキャンセル・軽量化の変更も含む。開始時点は `out/refactor-20260927/intake-source.zip` に保存した。機能の追加、データ形式や公開APIの変更、公開リリースは行わない。

## 試験条件

- 実アプリはこの作業ツリーからビルドする。ネイティブ試験は毎回専用の一時DBとWebView2プロファイルを使用する。
- UI比較の選択日は2026-09-25、天気応答は固定値。時計の変動部分とアニメーションは画像比較から除外する。1280×860と1024×800、倍率1、ライト／ダークを比較する。
- 予定はIDを固定した時間指定1件・終日1件、月に割り当てた2タグを基本にする。追加操作後は元の合成データへ戻す。
- 大量データは平日10件／日、30分刻み・同時間に重ならない固定分布。1千・1万・5万件で同じ処理を10回測る。件数・集計値も比較する。
- 計測は同一PC・同一Node/WebView2・同一デバッグビルド。これは初回ロード全体の高速化試験ではなく、日付検索・月次集計・変更なしの再取得とJSヒープの測定である。
- 性能の許容差は中央値で30%または2msの大きい方。JSヒープは20%または2MiBの大きい方。再描画数と未変更時のデータ本体転送量は0を維持する。生サンプル、中央値、p95を残す。
