# Outlook同期の対応範囲

更新日：2026-10-13。対象はWindowsのClassic Outlookです。全形式・全提供元の完全同期を保証するものではありません。

## 送信条件

| 全体の送信設定 | タスクの設定 | Calendar → Outlook |
|---|---|---|
| OFF（既定） | OFF | 送信しない |
| OFF（既定） | ON | 送信せず変更を保持 |
| ON | OFF | 送信せず両方の予定を保持 |
| ON | ON | 作成・編集・明示的な削除を反映 |

OFFへの切り替え自体は削除操作ではありません。待機中の処理と再試行にも同じ条件を適用します。実行中のCOM操作と設定保存は直列化します。タスクの既定ON／OFFは全体スイッチとは別です。

Outlook → Calendarの取得・自動取得は独立しています。取得範囲に重なる予定を取り込み、既知の連携先は個別にも確認します。リアルタイム通知ではありません。未送信のローカル編集は古い取得結果で上書きしません。

## 追加した項目

| 項目 | Calendarの扱い | Outlookとの連携 |
|---|---|---|
| 開始日・終了日 | 単日・複数日の入力、各日の表示と集計 | 1件の予定として反映 |
| 時刻・終日 | 秒も保持。終日終了日は包含、時刻付き深夜終了は翌日に重ねない | COMが秒を丸めるため非0秒の送信は停止 |
| 本文・場所 | メモと場所を分離 | 他項目のみの編集では本文書式を保持 |
| 通知・公開方法・秘密度・重要度・分類 | 詳細欄で編集 | Outlookが許可する属性を反映 |
| 開始・終了タイムゾーン | IDを保持・編集。日時はPCのタイムゾーンで入力 | Outlookのゾーン設定として保持 |
| 主催者・参加者・出欠 | 表示 | 招待・通知・回答はOutlookで実行 |
| 添付情報 | 名前・サイズ等を表示 | 通常編集では元の添付を保持。追加・削除はOutlookで実行 |
| 繰り返し | 6種類の規則、間隔、曜日、月日、第何曜日、終了条件 | ネイティブ系列と各回を区別し、マスターを重複作成しない |

AI向け検索・工数集計も期間内の部分を集計します。既存予定の編集提案では終了日・秒・詳細情報を保持します。AIへの送信権限追加ではありません。

## MECEで点検する軸

状態を上から該当するものに分類します。

1. 連携履歴がないローカル予定。
2. 連携履歴があり、ローカルの予定を削除済み。
3. 予定があり、未送信・処理中・失敗・系列変更の反映待ち。
4. 予定があり、送信OFFで同期済み状態から変更していない。
5. 予定があり、送信ONで反映完了。
6. 取得元・識別情報を確認できていない旧形式。

取得結果は「確認不能／取消済み／有効／不在を確認」、有効な予定は「変更なし／変更あり／比較情報なし」に分けます。通常予定・通常の定期系列・会議・独自形式を区別し、系列操作は今回／全体／以降に分けます。全組み合わせを全提供元で実機検証したという意味ではありません。

## 操作と保護

| ケース | 挙動 |
|---|---|
| 双方向の通常予定作成・変更 | 元の予定と連携し、取得内容の送り返しと重複を防ぐ |
| Outlookの削除・明示的な取消 | 同じ予定と確認できる場合に反映 |
| OFF中の編集 → ON | OFFでは送らず、ON後に最新値を対象とする |
| OFF中のOutlook側変更・削除・復元 | 受信を独立処理。未送信のローカル変更があれば保留 |
| OFFのタスクをローカル削除 → Undo | 送信OFFを保って受信を再開し、未送信の編集も保持 |
| 削除後の復元 | 削除時のスナップショットと同期済み比較情報を別保存 |
| 同時変更・古い取得応答 | 版を比較し、勝手に上書きしない |
| 取得失敗・権限不足・件数超過 | 不明を削除済みとみなさない |
| 単日／複数日、時間指定／終日の切り替え | 終了日時を保存し、各日の表示と集計に反映 |
| ネイティブ系列の単一回変更・削除 | 元の日時から対象の回を解決 |
| 通常系列の全体／以降の変更・解除 | 1つの系列ジョブを保存し、分割後の過去と未来を別グループにする |
| OFF中の系列再編集 | 未実行のジョブを更新し、古い変更を先に送らない |
| 個別変更を含む通常系列 | 保持可能な本文・RTF・通常添付・カスタム項目・削除例外を保持 |
| 系列分割の再試行 | 操作識別情報と結果記録で重複を防ぐ |

系列全体の送信は対象の各タスクのONも確認します。送信を試みて失敗した系列操作は、部分反映を無視して差し替えず、結果確認・再試行による復旧が必要です。通常タスクのUndoと系列変更全体のUndoは同じ機能ではありません。

## 残る制約

- COM経由では秒を含むStart／Endが分単位へ丸められることを確認しました。非0秒は無断で丸めず、入力を保持して送信を停止します。
- このPCの提供元ではMove復元でEntryID・GlobalAppointmentID・RecordKeyが変わりました。同一性を証明できない場合は件名の類似で結び付けません。新規取り込みと旧タスクのID・タグを保った復元は区別します。
- 会議の「この日以降」の分割や、会議の個別変更を含む規則変更は、参加者・通知・回答状態を保護するためOutlookで行います。
- OLE／埋め込み添付、計算式のカスタム項目、新規則に元の日付が残らない個別変更などは変更前に停止します。
- Outlookの単一回は秘密度・分類の書き込みを受け付けない場合があります。
- COMに複数操作の永続トランザクションはありません。通常エラー時の復元と検証済みの分割再開には対応しますが、全体変更の途中で強制終了した場合まで原子的に戻るとは保証しません。
- 新しいOutlook、全提供元・権限・タイムゾーン・夏時間の組み合わせは検証対象ではありません。

Microsoft Graphには同じメールボックス内の移動で変化しないIDがありますが、この実装はGraph接続ではありません。認証・アプリ登録と会議通知の動作確認が別途必要です。[MicrosoftのImmutable IDの説明](https://learn.microsoft.com/en-us/graph/outlook-immutable-id)

## 検証

全体・個別の送信ゲート、受信、Undo、系列分割、通常添付・例外保持、保存・復元、期間集計をRustと画面の回帰テストで確認します。

通常のRustテストでは実Outlookを操作するテストは無効です。ユーザーの了承なしに有効化・実行しないでください。
